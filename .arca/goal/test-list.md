# `uni-spec` test plan

Verification is document inspection and written state tracing. No test requires software execution.

## Verification

The verification checks are exactly `T-001` through `T-012`, one-to-one with `US-01` through `US-12`. Check IDs follow source verification-proposal encounter order.

| Check ID | Request Refs | Procedure | Expected Evidence |
| :--- | :--- | :--- | :--- |
| `T-001` | `US-01` | Inspect one issue directory and enumerate entries and kinds. | Evidence shows exactly the five named regular files, with no symlink, subdirectory, or extra entry; each file has its distinct aspect. |
| `T-002` | `US-02` | Inspect the current directory name and its target parent's direct-child directory collection. | Lint evidence shows `i-[0-9]{3,}-[a-z0-9]+(?:-[a-z0-9]+){1,3}`, a numeric value greater than zero (`000` fails), and uniqueness against every sibling directory beginning `i-<digits>-`, including malformed candidates such as `i-001-old`; it does not claim to derive a slug from an unpersisted title or prove historical stability. A conversion/state trace separately shows siblings `i-001-old` and `i-003-existing`, so the expected smallest unused positive allocation is `2` rendered as `i-002-...`; after creation, a later supplied-title change leaves both the folder name and `index.md` `issue-id` frozen. |
| `T-003` | `US-03` | Read `index.md` as bytes and parse its frontmatter strictly. | Evidence shows byte-1 `---`, a later exact closing `---`, no duplicate keys, exactly scalar keys `issue-id`, `origin`, and `status`, non-empty origin, an allowed status, and an issue-id matching the full directory name. |
| `T-004` | `US-04` | Inspect all five aspects. | Evidence shows each required heading, exact table columns and non-empty content or its exact absence declaration, no blank template token, and four index routes whose local destinations resolve under the link rules. |

## Evidence discipline

Every trace records observed text or structure, expected contract, and remediation where a rule fails. No trace treats a current workspace template as product authority, and no trace relies on forward or reverse authority links.
