# `uni-spec` specification

## Purpose

`US-01` through `US-12` define the uniform issue-folder standard and its written conversion/lint evidence only. They do not specify commands, APIs, executable runtime behavior, source or package requirements, dependencies, orchestration, apply or archive workflows, or implementation plans. The separately scoped `US-13` through `US-17` requirements govern selective recovery of this repository's historical CLI and its proof; they do not change the standard product boundary. `US-18` separately governs Windows-targeted command generation and shell-tool selection; it is platform guidance, not product behavior. `US-19` separately governs the repository's end-of-loop cleanup, current-goal promotion, and terminal-record archive lifecycle, and `US-20` widens that lifecycle's relocation scope to every terminal record in every collection. The separately scoped `US-21` through `US-26` requirements govern the `uni-spec` applier, an external tool that carries out this standard's written procedure; the dependency runs one way from applier to standard, so they add nothing to `US-01` through `US-12` and do not change the standard product boundary.

## Source requests

Each row is a stable source request. Disposition is one of `accepted`, `rejected`, `duplicate`, `deferred`, or `undecided`; the rationale records why that disposition is source-grounded.

| Request ID | Source ask | Disposition | Rationale |
| :--- | :--- | :--- | :--- |
| `US-01` | Define one issue folder with exactly five distinct regular files: `index.md`, `ubi-lang.md`, `spec.md`, `design.md`, and `test-plan.md`. | `accepted` | A fixed shape is the smallest uniform persistent standard and keeps each aspect distinct. |
| `US-02` | Require folder names `i-<nnn>-<slug>`, where `<nnn>` is the smallest positive integer (numeric value greater than zero; `000` is invalid) not used by any direct-child directory in the target folder's parent whose name begins with candidate pattern `i-<digits>-`, including otherwise malformed candidates such as `i-001-old`, and is rendered with at least three digits; derive `<slug>` from the first non-empty supplied title in source encounter order (after trimming and collapsing whitespace) using lowercase ASCII-alphanumeric `[a-z0-9]+` components, replacing non-ASCII-alphanumeric runs with `-`, trimming, taking the first four tokens, using `untitled-issue` for zero tokens, and appending `issue` to one token, then freeze both identity parts after creation. | `accepted` | Deterministic naming and frozen identity provide stable issue routing while malformed sibling candidates still reserve numbers. |
| `US-03` | Require `index.md` to begin at byte 1 with a strict YAML frontmatter block closed by `---`, containing exactly scalar keys `issue-id`, `origin`, and `status`; `issue-id` equals the full directory name, `origin` is non-empty, and `status` is `pending`, `integrated`, or `rejected`. | `accepted` | Identity, provenance, and lifecycle state must be parseable and unambiguous. |
| `US-04` | Require each file's aspect contract, non-empty required content or its exact absence declaration, no blank template tokens, and issue-local Markdown links that resolve under the link rules. Verification must use source-provided checks only; uncovered accepted or undecided request IDs use the exact listed no-source-verification statement, while no such IDs use the exact no-verification-required statement. | `accepted` | Complete, distinct content and navigable routes make a folder inspectable without inferred fields; explicit verification gaps prevent invented coverage. |
| `US-05` | Declaratively specify deterministic, source-grounded conversion from one or many legacy documents, tracker records, inline inputs, or broken folders: encounter sources in input order then documents in document order; select the first supplied title whose trimmed/collapsed value is non-empty, or use the first non-empty sentence of the first source ask, otherwise `Untitled issue`; assign `R-001`, `R-002`, and so on to asks in encounter order; preserve an explicit allowed disposition and non-empty rationale together, otherwise use disposition `undecided` with exact rationale `No source disposition or rationale provided.`; never invent verification checks or evidence. | `accepted` | A written, source-grounded conversion procedure keeps title selection, request mapping, dispositions, and verification gaps deterministic without making conversion runtime behavior. |
| `US-06` | Declaratively specify a complete lint contract for malformed and parsing-broken folders, including findings, continued evaluation, and a zero-finding pass rule. | `accepted` | Deterministic diagnostics are the guardrail for both ordinary and broken input. |
| `US-07` | Keep the standard docs-only: it defines no software implementation, command, API, executable runtime, source or package requirement, dependency, orchestration, apply or archive operation, or implementation plan. | `accepted` | The requested deliverable is a lightweight persistent standard, not a product or workflow engine. |

## Integrated repository-wide terminal archive requirement

This accepted requirement is the forward authority for [`R-001`](../issue/archive/i-005-terminal-archive-sweep/spec.md#source-requests), [`R-002`](../issue/archive/i-005-terminal-archive-sweep/spec.md#source-requests), and [`R-003`](../issue/archive/i-005-terminal-archive-sweep/spec.md#source-requests) in the terminal archive sweep issue; the issue is the reverse source record. It widens one clause of [`US-19`](#integrated-end-of-loop-archive-lifecycle-requirement) and changes none of its other terms.

| Request ID | Source ask | Disposition | Rationale | Reverse issue refs |
| :--- | :--- | :--- | :--- | :--- |
| `US-20` | The completion lifecycle relocates every terminal record in every collection — each `integrated` or `rejected` issue, `satisfied` residual, and `done` ticket, including records left live by earlier loops — beneath `.arca/issue/archive/`, `.arca/residual/archive/`, and `.arca/ticket/archive/`, so each live collection directly holds only nonterminal records and its reserved `archive/`. Every retention, preservation, or census check that names a relocated record resolves it at its live or archived location and counts live and archived records together, so a sweep is never observable as loss. | `accepted` | Terminal status, not loop ownership, is what makes a record finished; the loop-scoped restriction left earlier finished records in the live collections, which misreports remaining work while adding no safety. | [`R-001`](../issue/archive/i-005-terminal-archive-sweep/spec.md#source-requests), [`R-002`](../issue/archive/i-005-terminal-archive-sweep/spec.md#source-requests), [`R-003`](../issue/archive/i-005-terminal-archive-sweep/spec.md#source-requests) |

These accepted requirements are the forward authority for [`R-001`](../issue/archive/i-006-uni-spec-issue-generation/spec.md#source-requests) through [`R-006`](../issue/archive/i-006-uni-spec-issue-generation/spec.md#source-requests), [`R-008`](../issue/archive/i-006-uni-spec-issue-generation/spec.md#source-requests), and [`R-009`](../issue/archive/i-006-uni-spec-issue-generation/spec.md#source-requests) in the uni-spec issue generation issue; the issue is the reverse source record. `R-007` (executable `C0`-`C6` conversion) is `deferred` and carries no forward authority. These requirements govern a separately scoped applier only; they do not revise the docs-only product contract in `US-01` through `US-07`.

| Request ID | Source ask | Disposition | Rationale | Reverse issue refs |
| :--- | :--- | :--- | :--- | :--- |
| `US-21` | The applier's scaffold operation creates one issue folder holding exactly the five aspect files `index.md`, `ubi-lang.md`, `spec.md`, `design.md`, and `test-plan.md` as regular files and writes no sixth entry; a five-aspect artifact schema replaces the inherited four-artifact `spec-driven` set so artifact status, instructions, and template resolution report the five aspects and their dependency order (`index` requires nothing, `spec` and `ubi-lang` require `index`, `design` and `test-plan` require `spec`) instead of `proposal`, `specs`, `design`, and `tasks`; and every piece of operational state is derived from `index.md` frontmatter or stored beside the collection, never inside a package. | `accepted` | The package boundary in `US-01` forbids a sixth entry, so the inherited `.openspec.yaml` and `README.md` writes and the four-artifact vocabulary cannot coexist with a conforming folder; `US-03` already requires strict parseable frontmatter, so lifecycle state has an authoritative in-package home without a sidecar. | [`R-001`](../issue/archive/i-006-uni-spec-issue-generation/spec.md#source-requests), [`R-003`](../issue/archive/i-006-uni-spec-issue-generation/spec.md#source-requests), [`R-005`](../issue/archive/i-006-uni-spec-issue-generation/spec.md#source-requests) |
