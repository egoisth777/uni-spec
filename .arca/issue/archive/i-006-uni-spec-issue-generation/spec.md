# Specification

## Source requests

One user request is decomposed into nine requirement records. All nine are decided at P1 fold-in: `R-001` through `R-006`, `R-008`, and `R-009` are `accepted` and carry forward authority in the goal; `R-007` is `deferred` and carries none. Each rationale records the decision taken.

| Request ID | Source ask | Disposition | Rationale | Accepted Forward Authority Refs |
| --- | --- | --- | --- | --- |
| R-001 | Replace the CLI's OpenSpec change scaffold with a uni-spec issue scaffold: one command creates one directory holding exactly the five aspect files `index.md`, `ubi-lang.md`, `spec.md`, `design.md`, `test-plan.md` as regular files, and writes no sixth entry. | accepted | Replaced outright rather than kept behind a flag: `new change` writes `.openspec.yaml` and `README.md`, both forbidden inside an issue folder by the package boundary, so a flag would only preserve a shape the product never emits. | Goal [`US-21`](../../../goal/spec.md#integrated-uni-spec-applier-requirements); [applier mapping](../../../goal/design.md#integrated-uni-spec-applier-mapping); check [`T-021`](../../../goal/test-list.md#verification) |
| R-002 | Derive package identity from the standard's naming and allocation rule `i-[0-9]{3,}-[a-z0-9]+(?:-[a-z0-9]+){1,3}`, with the smallest unused positive integer among sibling `i-<digits>-` candidates including malformed ones, rendered with at least three digits, with the slug derived from the supplied title and both parts frozen at creation. | accepted | The applier owns allocation rather than accepting a caller-supplied id: `US-02` already fixes the algorithm completely, and a caller-supplied id reintroduces exactly the collisions and malformed names the rule exists to prevent. | Goal [`US-22`](../../../goal/spec.md#integrated-uni-spec-applier-requirements); [applier mapping](../../../goal/design.md#integrated-uni-spec-applier-mapping); check [`T-022`](../../../goal/test-list.md#verification) |
| R-003 | Replace the bundled four-artifact `spec-driven` schema with a five-aspect uni-spec schema, so artifact status, instructions, and template resolution report the five aspects and their dependency order instead of `proposal`, `specs`, `design`, `tasks`. | accepted | The uni-spec schema replaces `spec-driven` as the only schema the shipped applier carries rather than coexisting with it, because `R-009` already retires the surface that the four-artifact vocabulary serves. | Goal [`US-21`](../../../goal/spec.md#integrated-uni-spec-applier-requirements); [applier mapping](../../../goal/design.md#integrated-uni-spec-applier-mapping); check [`T-021`](../../../goal/test-list.md#verification) |
| R-004 | Generate every aspect file from the shipped `standard/templates/issue/` files, keeping the standard as the single template authority with no second copy inside the CLI. | accepted | Runtime resolution is the default and build-time embedding is permitted only with a byte-for-byte drift check, so divergence from the standard is always a failing check rather than a silent inconsistency. | Goal [`US-23`](../../../goal/spec.md#integrated-uni-spec-applier-requirements); [applier mapping](../../../goal/design.md#integrated-uni-spec-applier-mapping); check [`T-023`](../../../goal/test-list.md#verification) |
| R-005 | Keep all operational CLI state outside the issue package: recover status from `index.md` frontmatter, or store any sidecar beside the package rather than inside it. | accepted | Frontmatter-derived state is chosen over an external sidecar: `US-03` already requires `issue-id`, `origin`, and `status` to be strict and parseable, so the authoritative state already exists and a second store could only contradict it. | Goal [`US-21`](../../../goal/spec.md#integrated-uni-spec-applier-requirements); [applier mapping](../../../goal/design.md#integrated-uni-spec-applier-mapping); check [`T-021`](../../../goal/test-list.md#verification) |
| R-006 | Validate an issue package against the standard's `LINT-01` through `LINT-07` contract, emitting each finding with rule ID, path, line or null, observed, expected, and remediation, and reporting PASS only when every rule evaluated and recorded zero findings. | accepted | Validation ships in the same slice as generation: it is independent of the scaffold, `standard/examples/` already supplies fixtures and recorded expected findings as its oracle, and a generator without a checker cannot prove its own output conforms. | Goal [`US-24`](../../../goal/spec.md#integrated-uni-spec-applier-requirements); [applier mapping](../../../goal/design.md#integrated-uni-spec-applier-mapping); check [`T-024`](../../../goal/test-list.md#verification) |
| R-007 | Apply the standard's `C0`–`C6` conversion procedure when generating a package from existing sources, preserving source and document encounter order, title selection, `R-00n` assignment, and the exact absence and `undecided` declarations. | deferred | Deferred to a follow-up issue as the source itself proposed: conversion is the largest and riskiest slice, while scaffold and lint are useful and provable without it. This record carries no forward authority and gains none until a later planning pass folds it in; its source-provided check `C-009` is retained here as incoming evidence for that pass. | None; deferred records carry no forward authority. |
| R-008 | Keep the generator a separate implementation scope: `standard/` and requirements `US-01` through `US-12` stay docs-only, the CLI is an applier of the standard, and no standard document gains a command, API, runtime, or implementation-plan requirement. | accepted | The separation is now stated in the goal front door, the applier mapping, the docs-only boundary, and the `LINT-07` scope row, which are the four places a later contributor reads before touching the standard. | Goal [`US-25`](../../../goal/spec.md#integrated-uni-spec-applier-requirements); [applier mapping](../../../goal/design.md#integrated-uni-spec-applier-mapping); check [`T-025`](../../../goal/test-list.md#verification) |
| R-009 | Decide the disposition of the remaining inherited OpenSpec surface: the `openspec` binary name and the `change`, `archive`, `spec`, `store`, `workset`, `view`, `doctor`, `context`, and telemetry commands. | accepted | Decided with the reviewer: the binary is renamed to `uni-spec` and lives in `cli/` (`cli/bin/uni-spec.js`), carrying only the surface the standard defines - issue scaffold and lint. The root `openspec` heritage is frozen - no new work lands there - and is removed in a dedicated prune pass once `cli/` fully replaces it. | Goal [`US-26`](../../../goal/spec.md#integrated-uni-spec-applier-requirements); [applier mapping](../../../goal/design.md#integrated-uni-spec-applier-mapping); check [`T-026`](../../../goal/test-list.md#verification) |
